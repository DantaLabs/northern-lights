# Wave 5 bounded process-local drain admission

This pass wires one DrainGate to the shared SQLite opener, all production `/mcp` POSTs (including authentication/audit, provider work, and final response), and the assurance janitor. Startup migrations, bundle/bootstrap, mappings, and pending-write cleanup finish before the handler is returned. A local BackupManager uses that exact gate. Admission closes before backup, in-flight POSTs and janitor transactions finish, concurrent backup attempts fail, and SQLite `query_only` rejects raw writes on the shared single connection while the snapshot is created. Reset uses a bounded independent context; reset failure leaves the gate closed and `/readyz` unavailable. The in-process coordinator has a two-minute total timeout.

No authenticated maintenance endpoint or scheduled backup invocation exists: `productionHandler.maintenance` is internal-only, and the operational trigger remains unimplemented. The local signed envelope is not a durable Blob recovery gate. No Azure promotion, deploy, live provider operation, transfer production activation, restore-on-start fence scan/join, or full Wave 5 acceptance is claimed. All code that opens a second DB connection or writes outside the shared opener would require a separate admission audit; this boundary assumes the canonical single connection and single replica. Direct callers of `CreateBackup` with a separately constructed gate are local/test-only and not a production maintenance entry point.
